In real SeQaM experiments, phases last much longer than one second, so this is not a problem.

30. Why we need wrapper/publisher logic around tc_control.sh

tc_control.sh only changes the network.

It does not tell Kafka what happened.

It does not tell the app what phase is active.

It does not publish live network state.

It does not watch SeQaM phase changes.

So we added:

tc_controller.py

Purpose:

phase file changes  
→ choose matching tc_control.sh command  
→ apply tc command  
→ publish phase event to Kafka

network_conditions_publisher.py

Purpose:

read actual tc state every second  
→ parse active delay/jitter/bandwidth  
→ publish network metrics to Kafka

Together, they turn a simple shell script into a lab-ready network control module.
